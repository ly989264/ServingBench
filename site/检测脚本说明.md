# 现场检测脚本 check_site_state.py

`check_site_state.py` 是只读的现场检测脚本：把监控机和 test-glm53、glm53-1 的 P、D、proxy 机器的实际状态，与脚本里写下的假设（端口、容器、看板、数据源、目录、补丁文件）逐项比较。[`内网现状.md`](内网现状.md) 和 [`内网现状.yaml`](内网现状.yaml) 依据它的输出更新。

## 放置与运行

把脚本复制到监控机上任意一个目录（例如 `/data/grafana/tools/`），在监控机上以 root 运行：

```bash
python3 -I -S -B check_site_state.py --all --personal-dir /data/<个人目录>
```

| 参数 | 作用 |
|---|---|
| `--all` | 除监控机外，经 `ssh root@<机器>` 把脚本从标准输入传过去，检查 test-glm53、glm53-1 的 P、D、proxy 机器；机器表取自面板二集群目录的 `inventory.json`，proxy 机器取自 `ingest.json` 的 `fetcher_url`（test-glm53）和 `deploy.env` 的 `PROXY_MACHINE`（glm53-1） |
| `--personal-dir` | 监控机上放部署包和旧备份的个人目录（`<个人目录>` 的查法见 `内网现状.md` 附录 A）；不给时与它有关的项报「不存在」 |
| `--node p\|d\|proxy` | 在单台节点上运行时指定角色；配合 `--cluster test-glm53\|glm53-1` |
| `--container` | 指定 vLLM 容器名；默认按进程（`vllm serve` 或 `api_server`）自动找运行中的容器 |
| `--report-dir` | 报告目录，默认为脚本所在目录 |
| `--assume` | JSON 文件 `{编号: 预期值}`，替换脚本里的假设（假设更新或实验室测试时用） |
| `--lines` | 屏幕输出的行数上限，默认 150 |

不加 `--all` 时只查监控机。单台节点上单独运行：`python3 -I -S -B check_site_state.py --node d --cluster test-glm53`。

## 输出

- 屏幕：每台机器一段（结果相同的机器合为一段），一行汇总（一致 / 不一致 / 未知 / 无法检查），其后列出不一致的项，全部不超过 150 行。
- 报告：全部项和明细写入监控机上的 `report-<时间>.txt`，这是脚本唯一写的文件。节点上不写任何文件。
- 预期值为空的项（现状未知）直接打印实际值。

## 只读保证

- docker 只用 `inspect`、`ps`、`network inspect`；不进入 vLLM 容器执行命令，不发信号，不重启。
- 运行中容器的文件经 `/proc/<pid>/root` 读取，环境变量经 `/proc/<pid>/environ` 读取。
- ClickHouse 只经 `clickhouse-client --readonly=1` 执行 SELECT；Grafana 和入库进程的状态端口只用 HTTP GET；crontab 只用 `crontab -l`。
- 不打印口令：Grafana 账号从 `deploy.env` 读取后只用于请求，不出现在屏幕和报告里。

## 更新假设

现场变更（加集群、升级）后，假设与现场不再一致。改脚本开头「assumptions (data)」一段的数据，并同时更新 `内网现状.md` 与 `内网现状.yaml`；不要把现场的真实地址、个人目录写进脚本，个人目录只经 `--personal-dir` 传入。
