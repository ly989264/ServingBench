# Mooncake 替换前核对（glm53mc-5）使用说明

`dist/t51_mc_precheck.py`：只读核对现场的 Mooncake 包，判断能不能只换 `mooncake/libmooncake_store.so` 一个文件。操作说明 A 替换前的那一步用的就是它，是替换前的最后一道关。

## 1. 命令

每个要换库的容器都跑一次，在容器里的 vLLM 正在运行时跑。脚本自己找到 vLLM 进程，读它加载了哪些库。

```bash
docker cp t51_mc_precheck.py <容器名>:/tmp/
```

```bash
docker exec <容器名> python3 -I -S -B /tmp/t51_mc_precheck.py
```

```bash
docker exec <容器名> rm -f /tmp/t51_mc_precheck.py
```

**零影响：**
- 只用标准库，不导入 Mooncake；
- 不写任何文件（`-B`，不生成 `.pyc`）；
- 不联网、不起子进程、不发信号；
- 自己降到 nice 19，60 秒超时；
- 只读 ELF 文件头、节头、符号表和 `.rodata`，`libmooncake_store.so` 另读一遍算 sha256；另读 `/proc/<pid>/cmdline` 和 `maps`。

实验室用 strace 跟踪整次运行（第 4 节）：0 违规。

**输出：** 每边至多 20 行，照抄带回。加 `--show-names 20` 会在后面每族多打至多 20 个不同的名字（多出的行不受 20 行限制），只在要追查具体名字时用。

## 2. 每一行怎么读

| 行 | 内容 |
|---|---|
| `t51_mc_precheck=glm53mc-5 build=… pid=… loaded=…` | 脚本版本、内嵌的实验室数据标签、找到的 vLLM 进程号（`none` 表示没找到，改按标准目录找库）、它加载的库个数 |
| `mc_orig` | 现场 `libmooncake_store.so` 的大小和 sha16。`f1=same` 表示和小核对 f-1 带回的 17610953 / 3bf82f8b0c5ab715 相同。另有 SONAME、RPATH、NEEDED 个数、线程局部存储大小（`tls`，括号里是实验室的值）、包里 .so 的个数、有没有第二份 store 库 |
| `mc_build` | 是不是同一次构建（规则 1b）：`sections_other=` 是 `.rodata` 以外的编译产物节，`same` 表示类型、标志、大小全部和实验室核对件相同；`rodata` 一段是现场和实验室的 `.rodata` 大小、差值，现场构建路径的长度 `L'`、条数 `N'`（括号里是实验室的 `L`、`N`），不同前缀的个数，前缀的短哈希；`actual` 是实际差值，`predicted` 是按构建路径精确算出的差值，括号里分成 8 字节取整（`pad8`）和 16 字节对齐（`align16`）两部分，两者必须相等；`div4`、`div8` 和 `hint` 只作诊断，不参与判决 |
| `mc_size` | 文件总大小，只作参考：每次 patchelf 都会填充约 2.2 MB，不是编译出的代码 |
| `mc_exports` | 导出名的个数和指纹：现场、实验室核对件、替换库；不同的族；替换库和现场相比去掉、新增几个（规则 5，应为 `-0/+3`） |
| `mc_fam`（两行） | 按族分开的导出名，每族 `个数/指纹前 8 位`；族名后带 `!lab=…` 的，就是和实验室不同的族 |
| `mc_diff`（每个不同的族一行，最多 7 行） | 这一族现场多出的名字个数、实验室多出的个数，各举最短的一个名字（C++ 修饰名，截到 90 个字符） |
| `consumers_ok` 或 `mc_consumers` | 包里所有 ELF 文件（库、Python 模块、可执行文件）有没有引用替换库不再导出的名字（规则 3）。`consumers_ok n_elf=… removed_names=0`：补丁 04 不去掉任何名字 |
| `mc_revdep` | 包里别的库（以及进程里加载的 Mooncake 库）从 `libmooncake_store.so` 导入的名字：`文件=个数/指纹 covered=替换库能提供的个数` |
| `mc_imports` | 替换库自己要导入的名字（强引用）在现场能找到几个，缺的举一个；`verneed_missing` 是现场的 libc / libstdc++ 等缺的符号版本；`unchecked` 是没找到的库 |
| `mc_sib` | 兄弟库（libtransfer_engine、libmooncake_common、libasio、ascend_transport）的导出名，和实验室同一次构建比。不同的，括号里写出哪些族不同 |
| `mc_pre result=…` | 判决（第 3 节） |

族：
- 按名字所在的最外层命名空间分：`mooncake`、`std`、`msgpack`、`fmt`、`boost`、`asio`、`google`（glog、gflags）、`YAML`、`Json`、`tl`；
- `ylt` 是 yalantinglibs 一族（ylt、async_simple、coro_rpc、cinatra 等）；
- `rtti` 是类型信息和虚表（`_ZTI`/`_ZTV`/`_ZTS`/`_ZTT`）；
- `c` 是没有 C++ 修饰的名字；
- `other` 是其余的。

## 3. 判决规则（写在脚本里，跑之前就定）

| 结果 | 条件 | 怎么办 |
|---|---|---|
| `STOP_changed` | 现场 store 库的大小或 sha16 和 f-1 不同（库被动过） | 不换 |
| `STOP_second_copy` | 包里或进程里还有第二份 store 库 | 不换，带回 |
| `STOP_build_differs` | 不是同一次构建：`.rodata` 以外有编译产物节和实验室核对件不同；或者路径串不止一个前缀，或者 `.rodata` 的差值和按构建路径精确算出的不相等（见下） | 不换 |
| `STOP_model_inapplicable` | `.rodata` 里一条以 Mooncake 源文件相对路径结尾的字符串都没有，路径模型用不上 | 不换，带回 |
| `STOP_report(mooncake)` | `mooncake::` 一族的名字不同 | 不换，带回 |
| `STOP_align(…)` | 类型信息和虚表，或带版本号的第三方内联命名空间（`msgpack::vN`、`fmt::vN` 等）不同 | 不换；先把括号里的那个依赖对齐，重编 |
| `STOP_missing_exports` | 别的库要从 store 库导入的名字，替换库里缺 | 不换 |
| `STOP_consumer_refs_removed` | 包里有 ELF 文件引用替换库不再导出的名字 | 不换 |
| `STOP_export_delta` | 替换库和现场原库的导出名之差不是「去掉 0 个、新增恰好那 3 个」 | 不换 |
| `STOP_unresolved` | 替换库要导入的名字或符号版本，现场找不到 | 不换 |
| `STOP_incomplete` | 有要查的库没找到（vLLM 没在跑，库又不在标准目录） | vLLM 运行时再跑一次 |
| `ok_replace` | 以上都没有 | 可以按操作说明 A 替换 |

其余各族（`std`、`boost`、`asio`、`google`、`YAML`、`Json`、`tl`、`ylt`、`c`、`other`）可以不同，前提是导入全部覆盖、是同一次构建。

**`.rodata` 的预测（规则 1b）。**
- **为什么 `.rodata` 单独处理。** glog 的日志宏把源文件的完整路径（`__FILE__`）写进 `.rodata`，所以 `.rodata` 的大小随构建目录的路径长度变化，其他编译产物节不随它变。实验室核对件里有 N = 65 条这样的字符串，前缀是 `/build/src/`（L = 11）。
- **怎么量现场的路径。** 脚本在现场 `.rodata` 里找以这 65 个相对路径之一结尾的字符串，得到条数 `N'` 和前缀长度 `L'`。要求 `N' = N`，而且这些字符串只有一个前缀（`prefixes=1`）：现场是一次构建、一个源码目录；两个前缀即使一样长、内容不同，也停下。路径本身不打印，只打印 `L'`、`N'`、不同前缀的个数和前缀的短哈希。
- **预测值必须和实际差值完全相等，没有容差。** 预测分两部分：
  - **8 字节取整（`pad8`）。** 这 65 条字符串在 `.rodata` 里都从 8 字节对齐处开始，每条占「长度 + 1」向上取到 8 的倍数那么多字节。对每条字符串，用现场的前缀长度和实验室的前缀长度各算一次占用，相减后求和。
  - **16 字节对齐（`align16`）。** 字符串后面紧跟的数据按 16 字节对齐。字符串一共增加的量不是 16 的倍数时，后面的数据要再往后挪 8 字节，这一部分就是 +8，否则是 0。
  - 还要求每个相对路径在现场恰好出现一次，和实验室一样。
- **依据：两份路径更长的实验室构建都逐字节吻合。**
  - 长 1 个字符：实际 +96 = `pad8` +88 + `align16` +8；
  - 长 13 个字符：实际 +848 = `pad8` +848 + `align16` 0。
  - 两次都是 `.rodata` 以外各节逐个相等。实验室字符串块的结尾在 16 字节里的位置，从链接后的文件里看不出来，是由这两次构建定出的。
  - `build_precheck.py` 生成脚本时会重算这两份构建：预测和实际差一个字节就不生成。
- **为什么不留容差。** 留容差会放过同样大小的非路径差异，而那正是这一步要拦的「另一次构建」。判严了的代价只是不换库，面板二的 Mooncake 三段为空。第 4 节 T9 就是这种情况：只多 8 字节，也会停下来。
- **`div4`、`div8` 只作诊断。** 路径不同造成的差值本身也是 8 的倍数，所以这两项区分不了「只是路径不同」和「代码不同」。`hint` 只说差在哪里：`codegen(sections_other)` 表示 `.rodata` 以外的节不同；`paths` 表示路径串本身不符（前缀不止一个、条数不对，或者相对路径对不上）；`rodata_only` 表示路径串都对，只有 `.rodata` 的大小和预测不符。
- 先前报的「2113 B ≈ 65 × 32.5」是文件总大小的差，没有考虑对齐，作废。

## 4. 实验室结果

**环境。** `docker run --rm`，镜像 `quay.io/ascend/cann:9.2.0-a3-openeuler24.03-py3.11`。
- 现场样式的布局：未打补丁的核对件（msgpack 9.0.0，`c3bb5590…`），加上按现场文件名放好的兄弟库和自带库，以及 msgpack 9.0.0 编的未打补丁 store 模块。
- 另起一个命令行里带 vllm 字样、已经加载了 `mooncake.store` 的进程，充当运行中的 vLLM。
- 「测试版」是指内嵌的现场大小和 sha16 换成了被测文件自己的值，让 `STOP_changed` 不起作用，好看其他规则。

## 5. 同一份源码，为什么只换一个库也有风险

**同一份源码不等于同一份二进制。** 一个 C++ 库编出来的机器码，不只取决于它自己的源码，还取决于：
- 它包含的每个头文件的版本（msgpack、boost、yalantinglibs、libstdc++ 的头文件）；
- 编译器的版本和编译选项。

头文件里的模板会编进库本身。头文件版本不同，同一行源码就可能编出不同的代码、不同的符号名，结构体里的成员也可能排得不一样。

**这个库不是独立工作的。** `libmooncake_store.so` 和同一次构建出来的兄弟库（`libtransfer_engine.so`、`libmooncake_common.so`、`libasio.so`），以及 Python 模块 `store.so`，互相按符号名调用，还互相传递 C++ 对象。对象在内存里怎么排，调用的一方和被调用的一方必须一致。同一次构建出来的库天然一致；只把其中一个换成另一次构建的，就要看两次构建是不是在各方面都一样。

**不一样时，有两种结果。**
- **名字对不上。** 加载时直接报 undefined symbol，vLLM 起不来。这种情况容易发现、能回滚，但现场要停一次服务。
- **名字对得上，内存排布不一样。** 能加载、能运行，但读到的是错位的字段：可能算错值、崩溃，或者 KV 传输里的数据悄悄出错。这一种最危险，因为加载时没有任何报错。

**这次怎么确认是同一次构建。**
- **依赖版本。** 现场原库唯一和实验室不同的导出名，是 msgpack 的 `visit_ext`：参数是 `size_t`，只有 msgpack-c cpp-9.0.0 起才这样。实验室换成 cpp-9.0.0 头文件重编以后，导出名 10,974 个、指纹 `8d83f4262568bdd3`，和现场完全相同。
- **编译产物。** 代码、异常表、只读数据等各节的大小，只要编译器、头文件、选项有任何不同就会变，而 strip 和 patchelf 不改变它们。所以要求 `.rodata` 以外的各节逐个相等；`.rodata` 只允许差构建路径带来的那部分（第 3 节）。
- **补丁 04 对别的文件的影响。** 补丁只增加 3 个导出名、不去掉任何名字，包里其他文件引用的名字全都还在（`consumers_ok`）。

**为什么不直接换上去试。** 出问题的话，是现场的服务崩溃或数据出错；这次核对只读、几秒钟跑完。
