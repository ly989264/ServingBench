# glm5.3 现场小核对使用说明

脚本：`t51_glm53_fieldcheck.py`（单个文件，约 95 KB）。用途：不带回导出文件，也能回答 vllm-ascend 现场改动的几个问题和 Mooncake 替换库所需的事实。每个容器输出不超过 20 行（不加 `--show-diff` 时），可以照抄带回。

## 在哪里跑、怎么跑

一台 P 容器、一台 D 容器各跑一次，用运行 vLLM 的那个 `python3`，必须带 `-I -S -B`：

```bash
docker cp t51_glm53_fieldcheck.py <容器名>:/tmp/
```

```bash
docker exec <容器名> python3 -I -S -B /tmp/t51_glm53_fieldcheck.py --role P --run-dp-template <路径>/run_dp_template.sh --start-script <路径>/start_p.sh
```

D 上把 `--role P` 换成 `--role D`，`start_p.sh` 换成 `start_d0.sh`。加 `--show-diff` 时，另外打印被替换的 01 函数和 v0.30.0 原函数之间的 unified diff（两边都去掉公共缩进，最多 60 行，打印前把 IP、主机名、口令类的值、`/home/<用户名>`、`/data/<目录>`、工号样式的字符串换成占位符）；不加时不打印，每边不超过 20 行。两个启动文件的参数可以不传，不传就少两行 `launch`。跑完删掉脚本：

```bash
docker exec <容器名> rm -f /tmp/t51_glm53_fieldcheck.py
```

## 输出各行的含义

| 行 | 内容 |
|---|---|
| `t51_field=…` | 范围内的文件数（`vllm_ascend/patch/` 下全部 `.py`、`vllm_ascend/` 根目录的 `.py`、`kv_p2p/mooncake_connector.py`）；和 `d4ad49796` 相比改过、新增、缺少的个数；`conn_sha16` 是现场 `mooncake_connector.py` 的 sha256 前 16 位，P、D 两份比这一项 |
| `hist_changed`、`hist_added` | 每个改过或新增的文件，在公开 vllm-ascend 仓库 2026-08-15 以后的历史里有没有一模一样的版本：有就给出最早引入它的提交号、日期和包含它的分支（`main`、`v0.30.0` 等），路径不同时另注 `@原路径`；没有写 `none` |
| `monkey` | `patch/` 下每个改过或新增的文件，它替换掉的全部目标（按 Python 语法树找，不对照清单）：行首是文件的 sha256 前 16 位（`sha16=`，锁定版本）；每项写成「模块.类.名字(写法)」，写法有 `attr`（`X.y = …`，含整类替换）、`def+assign`（赋的是本文件定义的函数）、`setattr`、`dictset`（`vars(X)["y"]`、`X.__dict__["y"]`、`globals()["y"]`）、`rebind`（`from m import y` 以后在模块级又 `y = …`）；在我们的埋点清单里（`inputs/targets.txt`）的加 `*`。没替换任何东西的文件列在 `monkey none:` 一行 |
| `repl` | 被替换的目标里，凡是补丁 01 改过的函数（脚本内嵌了 vLLM v0.30.0 原版和打上我们移植之后的版本，共 19 个文件、98 个函数）各一行：`by=` 替换它的文件和行号；`sig=` 参数名列表是否和原函数相同；`wraps_orig=1` 表示新函数调用了替换前保存下来的原函数（`_orig = X.f` 再调 `_orig(...)` 一类），`0` 表示整份重写；`lines=现场/原版`；去掉首尾空白、跳过空行和注释以后和 v0.30.0 原函数比：相同 `eq`、插入 `ins`、删除 `del`、替换 `rep=原版行数/现场行数`，`at=` 是变动在 v0.30.0 文件里的行号（`^L` 表示插在这一行之前）；`01ctx=k/n` 是补丁 01 对这个函数的 n 处改动里，有 k 处的上下文行在现场函数里恰好出现一次；被替换的是 `AsyncLLM.add_request` 时另报 `addreq_calls=n[pos:k,owner:0/1;…]`：函数里 `self._add_request(` 的调用处数，每处的位置参数个数和是否传了 `owner=`（决定打补丁后会不会出 TypeError） |
| `p2d_replay` | P/D 传输补丁能不能在现场文件上重放：脚本逐字节内嵌了 `replay_p2d.py`（`script=` 是它的 sha256 前 8 位，运行时先核对 sha256，对不上写 `script=mismatch`；它的 `main()` 只定义、不调用），在内存里按它的 `--check` 跑一遍：31 条「停」判据（`facts=ok(31)` 或 `facts=stop stops=编号=现场值`）、28 处改动按锚点定位（`changes=28/28`，`alt=` 是用了备选锚点的改动和第几条，`left_out=` 是按设计可跳过而跳过的改动）、重放结果的检查和在内存里编译（`result=ok`，失败时给出退出码和原因）。什么都不写 |
| `p2d_extra` | p2d 的补充判据 X1–X6：脚本逐字节内嵌了 p2d 的 `extra_checks.py`（运行时先核对 sha256），在内存里对现场 `mooncake_connector.py` 调 `extra_line(源码)`。公开原版和 p2d 替换件上都是 `p2d_extra X1=1 X2=1/1 X3=2 X4=4/1 X5=1 X6=ok`，和原版不同的项后面带 `!` |
| `conn_funcs` | 现场 `mooncake_connector.py` 里和 `d4ad49796` 不同的函数：只列有变化的统计项，格式「项 公开值>现场值」；项有行数 `lines`、`batch_transfer_sync_read`（`bt_read`）、`request_queue.put`（`q_put`）、`_mark_request_task_done`（`task_done`）、`ensure_zmq_send/recv`、`retry`、循环数 `loops`；`=` 表示统计没变、只有文字不同；`+`、`-` 表示新增、删除的函数 |
| `mc_store` | Mooncake 包里含客户端 `BatchPut` 的库（补丁 04 要替换的就是它）：路径、大小、sha256 前 16 位、SONAME、RUNPATH（绝对路径写成 `<abs>`）、全部 NEEDED |
| `mc_syms` | 同一个库的导出符号数和导出符号名单的 sha256 前 16 位、导入符号数、是否导入 `__assert_fail`（`assert=1` 表示编译时没有 `NDEBUG`）、是否带 NVMe 测试桩（`nvme_stub`）、是否已含补丁 04 的计时行（`timing`）。用来和实验室编出的库逐项比对 |
| `glog_env` | 运行中的 vLLM Worker 个数，其中设了 `MC_LOG_DIR` 的个数，以及设了哪些 `GLOG_*`（只看变量名，不读值）。Mooncake `78566d45` 的传输引擎只在 `MC_LOG_DIR` 设了时才初始化 glog，并把日志写进那个目录；没设时写标准错误（`config.cpp:473–505`） |
| `launch` | 传了启动文件时才有：`vllm serve` 那一行里各参数是直接写的（`lit`）、经变量给的（`var`）还是没有（`absent`），`(file:n)` 是整个文件里出现的次数；`fwd_args=1` 表示那一行转发了 `"$@"` 一类的参数；`mtime=after_start` 表示文件在 vLLM 启动以后改过；`mc_log_dir=n` 是文件里出现 `MC_LOG_DIR` 的次数 |
| `read=…` | 读了多少、用了多久 |

超过 20 行时（且只在这时）依次压缩：`monkey` 各行合成一行（用 ` | ` 分隔），`launch` 两行合成一行，`read=` 移到第一行末尾；还超就截断并注明。不超时和 glm53f-1 的格式完全相同。

## 对环境的影响

- **会读的：** site-packages 里 `vllm_ascend` 范围内的 `.py` 文件和 `mooncake` 包里的 `.so`（`.so` 按 1 MiB 一块读，超过 1 GiB 不读；库的 ELF 头、动态段、符号表按偏移读）；传进来的两个启动文件；各进程的 `/proc/<pid>/comm`，以及 vLLM Worker 进程的 `/proc/<pid>/environ`（只取变量名）；传了启动文件时，还读 `/proc/stat` 的启动时刻、各进程的 `/proc/<pid>/cmdline` 和 `vllm serve` 进程的 `/proc/<pid>/stat`。
- **会写的：** 什么都不写，结果只打印到终端。`p2d_replay` 一项在内存里执行内嵌的 `replay_p2d.py`（只是定义和纯文本处理，不含它写文件的 `main()`），重放结果只在内存里编译，不落盘。
- **不做的：** 不导入 vLLM、vllm-ascend、torch、torch_npu、Mooncake，不执行 site-packages 里的代码（`-S`），不写 `.pyc`（`-B`，另设 `sys.dont_write_bytecode`）；不联网，不起子进程，不发信号，不读 `/proc/<pid>/mem`，不碰 NPU。开头把自己设为 `nice 19`，总耗时超过 120 秒就停。
- **少了 `-I -S -B`** 只打印一行 `REFUSED`，什么都不读。
- **实验室验证：** `lab/run_fc_lab.sh` 在模拟现场（`patch/__init__.py` 换成公开仓库更新的版本、新增一个替换埋点函数的 patch 文件、连接器改一个函数、根目录多一个文件）上用 `strace -f` 跟踪一次，结果见 `lab/results/`：没有任何以写方式打开的文件，没有网络调用，没有子进程，没有向其他进程发信号。
