# glm53-1：面板二接入与整集群打补丁（一页手册）

**做什么。** 一个脚本 `t53drive.sh`，在监控机上用 root 执行，按一份机器清单通过 `ssh root@<机器>` 并行操作所有机器，分六段：

| 段 | 做什么 | 集群 |
|---|---|---|
| ① | 只读预检：包、面板一的实例、每台机器的检测（T58 检测脚本）、启动文件、proxy 原文件 | 照常运行 |
| ② | 备份要换的文件（容器里、宿主机、监控机各一份），p2d 重放，装面板二的监控机部分（v3.4-extra，vllm 模式） | 照常运行 |
| ③ | 停下，等你整停集群；核对已停、容器没换 | 你整停 |
| ④ | 换文件（先第一个 D 并做导入核对，再其余并行），在启动文件里插两行 `export`，逐个核对 sha | 停着 |
| ⑤ | 停下，等你整启集群；核对 `/health`、命令行、检测结果、日志 | 你整启 |
| ⑥ | 看板归位，面板二的核对（过滤器自检、各段有值、留空比例、首批数据）；约 30 分钟后再核一次 | 运行 |

每段要所有机器都过了才进下一段。有一台没过就停，每台一行写原因。脚本从不停、起 vLLM 和 proxy：整停、整启由你按平时的方式做。

**每次执行的输出不超过几十行，带回的就是这些行。** 完整输出在监控机 `<状态目录>/<集群>/log/` 里，不用带回，要时再取。

**同一个脚本、两份清单。** 演练（glm53-test）和线上（glm53-1）只差清单：

| | glm53-test | glm53-1 |
|---|---|---|
| 机器 | P 1 台，D 1 台（DP 16） | P 8 台（每台 1 个实例），D 4 台（每台 16 个，DP 64） |
| 面板一 | 没有（面板二写进它自己的 Prometheus） | 有，面板二接在它上面 |
| 清单 | `lists/test-glm53.txt` | `lists/glm53-1.txt` |

## 准备（监控机，一次）

1. **放文件。** 在 `<工作目录>` 下解开 `t53-drive.tar`，再把下面几样放进 `<工作目录>/kits/`：
   - `t58-glm53-patch-kit.tar`（`4f59ea87…`）、`t58-glm53-mooncake-kit.tar`（`e3e338d5…`，`MOONCAKE=replace` 时）、`t51-glm53-proxy-kit.tar.gz`（`c08056fe…`，`PROXY=on` 时）；
   - 解开的面板包 v3.4-extra：目录 `vllm-pd-grafana-panel2/`（`b883692a…` 解开，含离线包）；
   - `proxy_new.py`：照 proxy 补丁改好的那份 proxy 文件（在 glm53-test 上改过的那份）。

   看板分层的目录 `看板分层与加集群/` 放在 `<工作目录>/` 下。

   ```bash
   cd <工作目录>/t53-drive && sha256sum -c SHA256SUMS | grep -v ': OK$'; echo 核对完
   ```

   **应当看到：** 只有一行 `核对完`。

2. **填清单。** 照 `lists/` 下的两份模板填 `<…>`：每台机器一行（地址、角色、端口）；proxy 那一行写 proxy 所在机器的地址、容器名、容器里 proxy 文件的路径；`PROXY_NEW_SHA256`、`PROXY_ORIG_SHA256` 写改好的文件和它对应的原文件的 sha256。容器、启动文件、日志由脚本从运行中的进程算出来，不用填。

3. **试一遍（不连任何机器）：**

   ```bash
   cd <工作目录>/t53-drive && ./t53drive.sh run lists/test-glm53.txt --dry-run && ./t53drive.sh run lists/glm53-1.txt --dry-run
   ```

   **应当看到：** 每份清单 5 行。第一行是机器数和实例数，glm53-1 是 `（只列出接下来要做的事，不连任何机器）集群 glm53-1：P 8 台 8 个实例，D 4 台 64 个实例，MOONCAKE=replace，PROXY=on；停在 pre`，test-glm53 是 `P 1 台 1 个实例，D 1 台 16 个实例`。后面 4 行是各段要做的事。清单有错时只打一行原因（例如 `第 15 行：地址 <P 机器 1 地址> 不对`）。

## 演练：glm53-test

先由你删掉 glm53-test，再用 glm53-1 的备份把它的容器恢复到初始状态，照平时的方式起来。然后：

| 步 | 你做什么（命令都在 `<工作目录>/t53-drive` 下执行） | 最后应当看到 |
|---|---|---|
| 1 | `./t53drive.sh remove-panel lists/test-glm53.txt` | test-glm53 是监控机上唯一的面板二集群时，先打一行影响：删插件要重启 Grafana，面板一的看板断几十秒，数据不丢；然后照删。删完是 `OK   test-glm53 的面板二已卸载。它的 deploy.env 留在 <路径>…`，再打出 `PANEL1_CLUSTER=-` 和 `PROMETHEUS_YML=…` 两行。把这个路径写进清单的 `ENV_FROM=`，并核对那两行和清单里的相同 |
| 2 | `./t53drive.sh run lists/test-glm53.txt` | ①② 每台一行 `OK`，然后 `整启前：在你们起 proxy 的启动脚本里加两个环境变量 PD_PROXY_DIAG=1、PD_PROXY_DIAG_DIR=/data/pd-diag/logs/proxy（…）`，最后是 `下一步：请整停集群（vLLM 和 proxy；不要 docker rm 容器），停完再执行 run。` |
| 2a | 在 proxy 的启动脚本里加上这两个变量（整启时 proxy 随集群一起起，⑤ 核对 proxy 进程带了这两个变量，没带就 `FAIL`） | — |
| 3 | 整停集群（vLLM 和 proxy），再执行 `./t53drive.sh run lists/test-glm53.txt` | ③④ 每台一行 `OK`，最后是 `下一步：请整启集群（启动方式和平时相同，不加 MC_LOG_DIR、PD_DIAG_LEVEL；proxy 用已加 PD_PROXY_DIAG=1、PD_PROXY_DIAG_DIR=/data/pd-diag/logs/proxy 的启动脚本起），起来以后再执行 run。` |
| 4 | 整启集群（proxy 用加好变量的启动脚本），再执行 `./t53drive.sh run lists/test-glm53.txt` | ⑤ 每台一行 `OK`；接着显示 `== ⑥ 等到拉起 5 分钟（HH:MM）`，在终端里等到那个时刻，再做 ⑥ 的第一次核对。最后是 `下一步：请在 HH:MM 以后再执行 run（留空比例和磁盘第二次）。` |
| 5 | 到那个时刻以后，再执行 `./t53drive.sh run lists/test-glm53.txt` | `结论：全部做完。面板二 test-glm53 在用，17 个实例都是 T58（没有面板一，不看 TPOT）。` |

## 线上：glm53-1

T64 现场升级做完以后（① 会核：监控机上没有 glm53-1 的面板二，各台没有旧面板二的 mock 在跑）。和演练的第 2–5 步相同，清单换成 `lists/glm53-1.txt`，没有第 1 步。第 5 步多一行面板一的 TPOT（只观测，不判），最后是 `结论：全部做完。面板二 glm53-1 在用，72 个实例都是 T58。`

## 没过、中途查看、线上出问题时的退路

- **没过：** 带回屏幕上的输出。按 `FAIL` 那一行的原因处理以后，再执行同一条 `run`，从没过的那一段接着做。
- **查看停在哪：** `./t53drive.sh status <清单>`。
- **退路（线上出问题时）：** `./t53drive.sh rollback lists/glm53-1.txt`。集群在跑时它先核对备份，再请你整停；整停后它还原 ② 备份的所有文件（启动文件里的两行 `export` 随之去掉，proxy 文件也还原），再请你照打补丁以前的方式整启（proxy 的启动脚本去掉那两个变量）；整启后再执行一次，核对回到打补丁以前。面板二留着，不影响 vLLM。演练不做这一步。
