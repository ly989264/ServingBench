# 10 面板一：服务侧 P/D 看板

面板一把每个 vLLM P/D 集群的服务侧指标显示成两张 Grafana 看板（Prefill、Decode）：节点上已有的指标端口由每个集群自己的 Prometheus 抓取，所有集群共用一个 Grafana。本文说明看板显示什么、由哪些组件组成、配置在哪里、怎样加集群、怎样改看板和出包、有哪些工具和已知陷阱。

约定与上下文：

- 占位符与 [01-全景](01-全景.md) 相同：`<ROOT>` 为面板目录的上级目录（手册里写作 `<总目录>`，内网取值 `/data/grafana`），`<用户目录>` 为监控机上放部署包和工具的个人目录，`<集群>` 为部署包里的集群名。
- 各集群的端口、目录等现场值见 [02-内网现状](02-内网现状.md)；必须遵守的规则见 [40-规则](40-规则.md)，本文按编号引用（如 P6、T4）。

## 2. 显示什么

### 2.1 两张看板

| 项 | Prefill 看板 | Decode 看板 | 出处 |
|---|---|---|---|
| 包内 uid / 标题 | `vllm-pd-prefill`「vLLM 服务侧监控面板 - Prefill实例」 | `vllm-pd-decode`「vLLM 服务侧监控面板 - Decode实例」 | 〔看板 JSON〕 |
| 每个集群装好后的 uid / 标题 | `vllm-pd-prefill-<集群>`，标题末尾加「（<集群>）」；dsv 集群由 `arrange_boards.py` 改成「（dsv4.1-flash-N）」 | `vllm-pd-decode-<集群>`，同左 | `scripts/gen_cluster.py`；`tools/boards_layout.txt` |

| 默认时间 | 最近 1 小时，不自动刷新 | 同左 | 〔看板 JSON〕 |

## 3. 组成与数据流

```
P、D 机器（现场已有的指标端口）                 监控机
  每个 vLLM 实例的 API server /metrics  ─┐
  每台机器的 npu-exporter（默认 8082）   ├─→ 每个集群一个 Prometheus ─→ 数据源「Prometheus（<集群>）」─→ 共用 Grafana
  每台机器的 node_exporter（默认 9100）  │    vllm-pd-prometheus-<集群>          （经 Docker 网络按容器名访问）    两张看板
  每个集群一个 Mooncake master 指标端口 ─┘
  （打 vllm-ascend 指标补丁后，另有每进程的 Mooncake client、TE 指标端口）
```

| 组件 | 说明 | 出处 |
|---|---|---|
| exporter | 部署包不在节点上装任何东西。npu-exporter、node_exporter 由现场安装，端口与 glm53-1 相同；每个实例有自己的 API server，没有跨两台机器的实例；内网不打 vllm-ascend 指标补丁（清单 `vllm_ascend_patched: false`） | 〔说明书〕0.4 |
| Prometheus | 镜像 `prom/prometheus:v3.11.2`；每个集群一个容器 `vllm-pd-prometheus-<集群>`、数据卷 `vllm-pd-prometheus-data-<集群>`；`prometheus.yml` 只读挂入，带 `--web.enable-lifecycle`，改清单后热加载；抓取间隔 15s、超时 10s；保留期写在 `prometheus.yml` 的 storage 段（内网 15d，实验室镜像 2h） | `scripts/gen_cluster.py` 的 `prometheus_cmd`；`prometheus/gen_prometheus_yml.py`；[40-规则](40-规则.md) X1 |
| 数据源 | 经 Grafana API 建，名称「Prometheus（<集群>）」，uid `prometheus-<集群>`，地址 `http://vllm-pd-prometheus-<集群>:9090`，`timeInterval` 等于清单的 `scrape_interval` | `scripts/gen_cluster.py` 的 `datasource` |
| Grafana | 12.4.2，所有集群和面板二共用一个，不由面板一的 `add` 安装。看板经 API 导入（`overwrite: true`）到顶层文件夹 `MODEL_GROUP`，再由 `arrange_boards.py` 挪进两层文件夹 | `scripts/gen_cluster.py` 的 `grafana_add`；`tools/arrange_boards.py` |
| 与面板二的关系 | glm53-1 的面板二借用面板一的 Prometheus 做采集链路告警：`prometheus.yml` 里有面板二写的标记段 `# BEGIN/END vllm-timing …`，`add` 重写文件时原样保留标记段和已有的 `rule_files` | `scripts/gen_cluster.py` 文件头；〔包 README〕「同一台监控机上再加一个集群」 |

包内 README 的步骤 1–31 是另一种装法：单集群、自带 Grafana 和 Prometheus、看板由文件 provider 加载（uid 不带集群名，文件夹「vLLM P/D」）。内网 2026-11-12 之前的旧面板一就是这种装法；现在的 8 套都是 `panel1_cluster.sh add` 装的（〔说明书〕0.1「部署包」；《面板一、面板二新装操作单》第 4 步，T26，2026-11-12）。旧面板一有《停用旧面板一操作单》（Caching 仓库 ServingBench 分支，2026-11-12）；T52 摸底时（2026-11-19）实验室镜像的 Grafana 共 18 张看板，其中已没有旧面板一的两张；内网是否已执行停用：未核实。

### 5.2 `names.py` 的名称与端口规则

`scripts/names.py` 面板一、面板二各带一份，内容相同（sha256 前 8 位 `3162da0a`，〔核对〕）。改它时两个包都要换、都要重新出包。规则（出处：`scripts/names.py` 文件头与 `RULES`）：

| 键 | 留空时的推导（集群 `<c>`，端口基数 `B`） |
|---|---|
| `PANEL1_DIR` | `<ROOT>/vllm-pd-grafana-panel1/<c>`；`<ROOT>` 依次取 `deploy.env` 的 `VLLM_PD_ROOT`、注册表的 `root`（由 `add --root` 写入）、`$HOME` |
| `PROMETHEUS_CONTAINER`、`PROMETHEUS_VOLUME` | `vllm-pd-prometheus-<c>`、`vllm-pd-prometheus-data-<c>` |
| `PROMETHEUS_PORT` | `B + 2`（面板二占 `B + 0` ClickHouse、`B + 1` 拉取程序） |
| `PROMETHEUS_DS_UID`、`PROMETHEUS_DS_NAME` | `prometheus-<c>`、`Prometheus（<c>）` |
| `PANEL1_P_UID`、`PANEL1_D_UID` | `vllm-pd-prefill-<c>`、`vllm-pd-decode-<c>` |
| `PANEL1_TITLE_SUFFIX` | `（<c>）` |

- 端口段：`B` 取 18100 到 19990 之间、步长 10 的段，`alloc` 给出第一个没人登记、也没被占用的段，`--port-base` 可指定。实验室镜像里 glm53-1 为 18100、test 为 18110、新加的 7 套为 18120–18180；内网各集群的值见 [02-内网现状](02-内网现状.md)。
- 防误用：每一步建容器、占端口或写 Grafana 之前先 `check`。名字、端口、UID 或机器与别的集群重复，或端口被别的程序占用，就在建任何东西之前停下；集群自己的容器不算冲突，所以每一步都能重跑。一台机器只能属于一个集群（〔说明书〕第 10 步 FAIL 表）。

## 6. 加集群、改集群、删集群

完整步骤按〔说明书〕执行（每步有命令、预期输出和 FAIL 处理）。主线如下，变量和目录以说明书第 2 步为准：

- **改某一套的机器或端口：** 改 `clusters.txt` 里这一套的行，重做「生成清单」到「核验」。重跑 `add` 就是更新：`prometheus.yml` 重写并热加载，Prometheus 不重启；两张看板按部署包重新导入，界面上的修改被覆盖（〔说明书〕第 5 节）。

## 10. 已知陷阱

| 陷阱 | 处理 | 出处 |
|---|---|---|
| 文件预置的看板会被改回：内网旧面板一的两张看板由文件 provider `vllm-pd` 加载，`allowUiUpdates=true`、`updateIntervalSeconds=30`，经 API 的每次保存都在 4–22 秒后被「预置加载」改回（实验室只在改文件或重启时改回）。〔UPDATE〕「改完又变回去时」的原因说明仍是实验室的行为 | 改这类看板只能写 provider 读的 JSON 文件：先备份，再覆盖，等一个扫描间隔，然后 `diag_panel1.py`（`现在：改动后`，连读 20 次不变）和 `diff_panel1.py`（0 处）。8 套集群的看板是经 API 导入的，不受 provider 管理，改它们的方法是第 7.5 节的重跑 `add` | T23，2026-11-11；T4 |
