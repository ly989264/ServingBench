## 给 W1 的一段话（打补丁手册照抄）

> **节点目录：** 沿用 test 的 `/data/pd-diag`，容器里的路径相同。面板手册第 3 步在两台机器上核对 vLLM 容器能在同一路径看到 `/data/pd-diag/conf` 和 `/data/pd-diag/logs`；两台都能看到时，打补丁手册不用加挂载、不用重建容器。有一台看不到时，面板手册第 3 步停下，由我们另定目录，挂载那一项再加进打补丁手册。
>
> **两个环境变量：** 放在容器里执行 `vllm serve` 的那个脚本里、`vllm serve` 之前，一台机器一组，所有 rank 共用；写在宿主机的 shell 或别的脚本里不生效。脚本里已经有 test 留下的同样两行时不用重复加：
>
> ```
> export VLLM_LOGGING_CONFIG_PATH=/data/pd-diag/conf/pd_diag_logging.json
> export PYTHONPATH=/data/pd-diag/conf${PYTHONPATH:+:$PYTHONPATH}
> ```
>
> **挂载**（只在面板手册第 3 步看不到 `/data/pd-diag` 时才要）：`-v /data/pd-diag/conf:/data/pd-diag/conf:ro -v /data/pd-diag/logs:/data/pd-diag/logs`
>
> **顺序：** 面板手册第 15 步（`add` 的 `RESULT: OK`，两台机器的 `/data/pd-diag/conf` 里已经是 test-glm53 的三个节点文件）做完以后，再打补丁、重启 vLLM；重启以后回到面板手册第二部分（第 16 步起）。

## 已知问题（和手册附录 B 相同）

1. 第 8 步的 `grep -ic test` 是子串匹配，标题里带 latest 这类的项也会命中。不是 0 时，先看命中的是不是 test 的东西（第 8 步「不对时」写明了）。
2. 实验室的替身没有本套补丁，所以：
   - 第 19 步的段数比现场少（替身不写的 10 段为空）；
   - 第 21 步有两条 FAIL；
   - 第 22 步前两列是全部记录数。
3. 如果打补丁手册第 2 步（打补丁前检测）的 run 行是 `logcfg=set`，说明现在的 vLLM 里挂着 test 留下的旧过滤器。分批重启期间，还没重启的那几批会继续往 /data/pd-diag/logs 写旧格式的记录，test-glm53 会把它们收进库，`check` 的过滤器版本在最后一批做完以前不会全部一致。是 `logcfg=unset` 时，没有这个问题。
4. 实验室里 test 是 vllm 模式，第 5 步的 `bin/nodes.sh stop` 在实验室里没有可停的进程。
5. 第 22 步的自检计数查询用的是 `GROUP BY node, instance, pid`。补丁包操作说明 A 第 7.3 节里这条查询已经改成 `GROUP BY instance, pid`，以补丁包那份为准。
